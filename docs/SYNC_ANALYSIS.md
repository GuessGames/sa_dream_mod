# Аналіз проблем синхронізації / Sync issues analysis

Стан на 2026-10-04, upstream `Tornamic/CoopAndreas` @ `89aafba` (v0.3.0-alpha).

## Як працює зараз
- Після підключення **кожен** клієнт вмикає генерацію перехожих і трафіку (`RevertTemporaryPatches` у `PacketHandlers/system.cpp`).
- Хук `CWorld::Add` робить кожну локально створену сутність «своєю» (`CreateHosted`) і розсилає її іншим.
- Сервер лише пересилає пакети: не стежить за відстанню, не передає власника, не веде облік.

## Проблеми (за пріоритетом)

### P0
1. **Зникання педів/машин.** Власник видаляє масовку поза своєю камерою → `PedRemove`/`VehicleRemove` у всіх. При виході гравця всі його сутності видаляються (`RemoveAllHostedAndNotify`), без передачі власника.
2. **Подвійна масовка → переповнення пулів.** Кожен клієнт генерує повну щільність + отримує копії (MISSION-сутності не враховуються генерацією).
3. **Пікапи (гроші, зброя) не синхронізуються взагалі.**
4. **`CPacketBuffer` пересортовує надійні події** (SPAWN/REMOVE) за часом відправника, тож події різних гравців міняються місцями.
5. **Миттєве повторне використання ID** + ненадійні SYNC-пакети → телепорти; `CNetworkPed` не перевіряє дубль ID.
6. **Сутність, видалена до `CONFIRM`,** не надсилає REMOVE; потім у список потрапляє вказівник, що вже нікуди не веде, і слот пулу може зайняти інший пед.

### P1
7. `ASSIGN_PED/VEHICLE` — це перемикач (toggle), а не явний стан; один втрачений пакет назавжди інвертує власника.
8. Без інтерполяції позицій педів/машин без водія.
9. Пауза/згорнуте вікно = немає мережі → таймаут → видалення сутностей.

### P2
- `VEHICLE_REMOVE` на сервері без `delete`; `GetFreeId()` = -1 не обробляється; інвертована перевірка спецактора (`strncasecmp`).

## Узгоджений план
- **Етап А:** масовку генерує тільки хост; сутності не видаляються, поки поруч є гравець; передача власника при виході; синхронізація пікапів.
- **Етап Б:** сервер як суддя (реєстр, ліміти по районах), власник — найближчий гравець, генерація лише одним гравцем у районі.
- Супутні виправлення: явний ASSIGN, без миттєвого повтору ID, події без пересортування.

## Діагностика
Логи: `<гра>\CoopAndreas\logs\server.log`, `client.log`, `client_1.log`, `client_2.log`.
Мітки: `[ped]`, `[veh]`, `[net]`. Аномалії пишуться як `[warn]`: дубль ID, видалення до CONFIRM, невідома сутність в ASSIGN, повний пул.
